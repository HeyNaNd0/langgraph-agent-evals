# Friction log

What confused me while learning LangGraph + LangSmith from zero, logged as it happened.

| # | Area | What I was doing | Expected | Actual | Time lost | Suggested fix |
|---|------|------------------|----------|--------|-----------|---------------|
| 1 | Getting-started docs: OpenAI key prerequisite | Getting an OpenAI API key for my first LLM call | My ChatGPT subscription would cover the API calls | API usage is billed separately ([OpenAI help](https://help.openai.com/en/articles/9039756-managing-billing-for-chatgpt-and-the-api-platform)), so I had to add $10 of credit first. Afterward I checked the [Tracing quickstart](https://docs.langchain.com/langsmith/observability-quickstart): its prerequisites list "An OpenAI API key" with no note about cost. | __ min | Add one line under that prerequisite: "OpenAI API usage is billed separately from ChatGPT plans; add API credit before you start." |
| 2 | Install docs: Python environment setup | Installing LangGraph and LangSmith on WSL (Ubuntu 24.04) | Copy the install commands and go | Stock Ubuntu has no `python` command (only `python3`), and `python3 -m venv` needs `sudo apt install python3-venv` first. The [install page](https://docs.langchain.com/oss/python/langgraph/install) shows only `pip install -U langgraph`, and the [Tracing quickstart](https://docs.langchain.com/langsmith/observability-quickstart) uses `python -m venv`, which fails here. | __ min | Add a short "Set up a virtual environment" step with Linux/WSL commands: `sudo apt install python3-venv`, `python3 -m venv .venv`, `source .venv/bin/activate`. |
| 3 | Tracing quickstart: setting API keys | Setting my LangSmith and OpenAI keys | One clear way to store keys | The quickstart uses `export` in the shell, which only lasts for that terminal session. My project uses a `.env` file with `python-dotenv`. The quickstart doesn't mention `.env` or explain when to use which. | __ min | Show the `.env` + `load_dotenv()` option next to `export`, with a note that `export` only lasts one terminal session. |
| 4 | LangGraph Studio: graph drawing | Opening my graph in Studio for the first time | See `parse` branch to `review` and `reject` | Studio drew `review`, `roast`, and `reject` as disconnected boxes, so my graph looked broken even though it ran fine. Fixed by adding a `Literal["reject", "review"]` return type to the routing function. The [Graph API overview](https://docs.langchain.com/oss/python/langgraph/graph-api) "Conditional edges" section doesn't mention this; it's only explained for `Command`. | __ min | In "Conditional edges," note that routing functions need a `Literal` return type (or a path map) for Studio to draw branches, or have Studio flag routers with unknown destinations. |
